# Разработка витрины и решение ad-hoc задач

Проект по подготовке витрины данных маркетплейса «ВсёТут» и решению четырёх аналитических задач на её основе.

## TL;DR

- **Данные**: маркетплейс «ВсёТут» (заказы, пользователи, платежи, регионы)
- **Стек**: PostgreSQL, DBeaver
- **Результат**: витрина `product_user_features` + 4 аналитических запроса
- **Ключевые метрики**: 62 408 пользователей, 64 562 заказа, средний чек 2 608

## О проекте

**Бизнес-контекст**: анализ поведения пользователей маркетплейса для сегментации, выявления паттернов покупок и региональных различий.

**Что сделано**:
- Спроектирована и наполнена витрина данных с агрегированными характеристиками пользователей
- Решены 4 ad hoc задачи: сегментация, ранжирование, региональная статистика, сезонность активности


## Данные

Схема `ds_ecom`, включающая таблицы:

| Таблица                         | Описание                   |
| ------------------------------- | -------------------------- |
| `ds_ecom.orders`                | Заказы пользователей       |
| `ds_ecom.users`                 | Информация о пользователях |
| `ds_ecom.order_payments`        | Платежи по заказам         |
| `ds_ecom.order_reviews`         | Отзывы и рейтинги заказов  |
| `ds_ecom.order_items`           | Товары в заказах           |


## Витрина данных

### Схема

Витрина `product_user_features` содержит агрегированные метрики по каждому пользователю:

| Поле                     | Описание                                              |
| ------------------------ | ----------------------------------------------------- |
| `first_order_ts`         | Дата первого заказа клиента                           |
| `last_order_ts`          | Дата последнего заказа клиента                        |
| `lifetime_days`          | Разница между первым и последним заказом (активность) |
| `total_orders`           | Количество заказов                                    |
| `avg_order_score`        | Средняя оценка заказов (0, если отзывов не было)      |
| `num_orders_with_rating` | Количество заказов с рейтингом                        |
| `num_canceled_orders`    | Количество отменённых заказов                         |
| `canceled_orders_ratio`  | Доля отменённых заказов                               |
| `total_order_costs`      | Суммарная стоимость доставленных заказов              |
| `avg_order_cost`         | Средняя стоимость заказа                              |
| `num_installment_orders` | Количество заказов в рассрочку                        |
| `num_orders_with_promo`  | Количество заказов с промокодом                       |
| `used_money_transfer`    | Использовал ли денежный перевод (1/0)                 |
| `used_installments`      | Использовал ли рассрочку (1/0)                        |
| `used_cancel`            | Отменял ли хотя бы один заказ (1/0)                   |

## Задачи (Ad hoc queries)

| Файл                       | Задача                                               | Ключевые техники                  |
| -------------------------- | ---------------------------------------------------- | --------------------------------- |
| `01_create_data_mart.sql`  | Создание витрины `product_user_features`             | агрегация, `FILTER`, `CASE`       |
| `02_user_segmentation.sql` | Сегментация по количеству заказов                    | `CASE`, группировка               |
| `03_user_ranking.sql`      | Топ-15 пользователей по среднему чеку (от 3 заказов) | `ORDER BY`, `LIMIT`               |
| `04_region_stats.sql`      | Статистика по регионам                               | агрегация, расчёт долей           |
| `05_monthly_activity.sql`  | Активность по первому месяцу заказа в 2023           | группировка по месяцу, сезонность |

## Выводы по задачам

### Задача 1. Сегментация пользователей
Пользователи разделены на сегменты по количеству заказов:
- 1 заказ;
- 2–5 заказов;
- 6–10 заказов;
- 11 и более заказов.

Для каждого сегмента рассчитаны:
- общее количество уникальных пользователей;
- среднее количество заказов;
- средняя стоимость заказа.

| Критерий             | Значение                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| Всего пользователей  | 62 408                                                                                              |
| Доминирующий сегмент | 96,89% (60 468 пользователей) сделали только 1 заказ                                                |
| Средний чек          | Самый высокий у сегмента «1 заказ» — 3 324; у постоянных клиентов (6–10 заказов) снижается до 1 245 |
| Общий средний чек    | 2 608                                                                                               |
**Инсайт**: большинство пользователей — разовые покупатели с высоким средним чеком. Удержание и повторные покупки — зона роста.

### Задача 2. Ранжирование пользователей

Отсортированы пользователей, сделавшие 3 заказа и более по убыванию среднего чека. Выведены 15 пользователей с самым большим средним чеком.

**Выводы:**

- **Максимальный средний чек**: 14 716
- **86% пользователей** из топ-15 сделали ровно 3 заказа
- **Максимальное количество заказов** у одного пользователя — 5 (средний чек 7 597)

**Инсайт**: в топ по среднему чеку попадают пользователи с минимальным количеством заказов (3–5), что может указывать на крупные разовые покупки.

### Задача 3. Статистика по регионам

Для каждого региона рассчитаны:

- общее количество клиентов;
- общее количество заказов;
- средняя стоимость одного заказа;
- доля заказов в рассрочку;
- доля заказов с промокодами;
- доля пользователей, совершивших отмену заказа хотя бы один раз.

| Критерий                           | Значение                                         |
| ---------------------------------- | ------------------------------------------------ |
| Всего пользователей                | 62 408                                           |
| Москва                             | 39 386 пользователей (63,11%), 17 661 заказ      |
| Новосибирская область              | 11 401 заказ (17,66%)                            |
| Средний чек (Санкт-Петербург)      | 3 620 (макс.)                                    |
| Средний чек (Москва)               | 3 168 (мин.)                                     |
| Доля покупок в рассрочку           | в Москве на ~6,5% ниже, чем в СПб и Новосибирске |
| Средняя доля заказов с промокодами | 3,86% по трём регионам                           |
| Доля отмен                         | Новосибирск 0,43%, СПб 0,53%, Москва 0,63%       |
**Инсайт**: Москва — крупнейший рынок по объёму, но с самым низким средним чеком и меньшей склонностью к рассрочке.

### Задача 4. Активность пользователей по первому месяцу заказа в 2023

Пользователи сгруппированы по месяцу первого заказа в 2023 году.  
Для каждой группы рассчитаны:
- общее количество клиентов;
- число заказов;
- средняя стоимость заказа;
- средний рейтинг заказа;
- доля пользователей, использующих денежные переводы при оплате;
- средняя продолжительность активности пользователя.

| Критерий                                      | Значение                                           |
| --------------------------------------------- | -------------------------------------------------- |
| Сезонность                                    | с мая по декабрь — 24 327 заказов (83,27% от года) |
| Средний чек                                   | от 2 581 (февраль) до 3 312 (сентябрь)             |
| Средний рейтинг за 2023                       | 4,18                                               |
| Денежные переводы                             | доля от 19,01% (ноябрь) до 22,11% (февраль)        |
| Продолжительность активности в январе         | 12 дней (макс.)                                    |
| Продолжительность активности в ноябре-декабре | 2 дня (мин.)                                       |
**Инсайт**: выраженная сезонность с пиком во второй половине года. Пользователи, пришедшие в начале года, активнее и дольше остаются на платформе.

## Как запустить

1. Подключитесь к базе данных PostgreSQL
2. Выполните `01_create_data_mart.sql` — создаст витрину `product_user_features`
3. Поочерёдно выполняйте запросы из файлов `02_`–`05_`
